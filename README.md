# КейсПортал

Платформа для проведения кейс-чемпионатов и лекций: витрина событий, регистрация команд, загрузка решений, судейство по критериям, таблица лидеров и инструменты для организаторов.

Стек: **Next.js (App Router) + Refine v5 + Supabase** (Postgres, Auth, Storage, pgvector, pg_net).

## Возможности

### Для участников
- **Умная витрина событий** — лента с персональными рекомендациями (теги интересов + нейро-эмбеддинги BGE-M3, затухание сигналов по времени, «с этим событием также»).
- **Регистрация** — команда с названием и выбором кейса или запись на лекцию; лист ожидания при лимите мест.
- **Решения** — загрузка файла в Supabase Storage после одобрения заявки.
- **Таблица лидеров** — публичный рейтинг с режимом нормализации оценок.
- **Дипломы** — автоматическая генерация диплома участника.
- **Календарь, избранное, подписки на организаторов, уведомления** (внутренние, с триггерами на все ключевые события).

### Для организаторов
- **Создание мероприятий** — форматы «кейс-чемпионат» и «лекция», кейсы, критерии оценки, темы, обложки, лимит мест.
- **Мультиарендность** — организации с ролями (owner / admin / manager), приглашения по e-mail, командная работа над событиями.
- **Слепое судейство** — судьи не видят авторство работ до публикации итогов.
- **Нормализация оценок** — z-score калибровка компенсирует строгость/щедрость судей, индекс 0–100.
- **Дашборд** — статистика, воронка заявок, управление статусами, состав жюри, экспорт в XLSX.
- **Уведомления** — заявки, решения, судейство, публикация итогов.

### Интеграции
- **MCP-сервер** (`mcp/`) — управление чемпионатами через ИИ-ассистента (Claude, Cursor и др.): создание событий, заявки, судьи, черновики оценок, публикация итогов, отчёты.
- **REST API v1** (`docs/API.md`) — каталог событий, заявки, лидерборды для внешних HR-систем.
- **Webhooks** — `registration.created`, `registration.status_changed`, `solution.uploaded`, `results.published` с HMAC-подписью (pg_net).

## Быстрый старт

1. Создайте проект на [supabase.com](https://supabase.com).
2. Выполните в SQL Editor по порядку:
   `supabase/schema.sql` → `migration_features.sql` → `migration_phase2.sql` → `migration_tags.sql` → `migration_works.sql` → `migration_favorites.sql` → `migration_team_capacity_social.sql` → `migration_embeddings.sql` → `migration_smart_feed_v3.sql` → **`migration_organizations.sql` → `migration_scoring.sql` → `migration_api.sql`**
   (миграции идемпотентны; последние три добавляют организации, слепое судейство и API).
3. Скопируйте `.env.example` → `.env.local`, подставьте URL, ключи и учётку организатора для MCP.
4. Запустите:

```bash
npm install
npm run dev        # портал: http://localhost:3000
```

5. (опционально) Умная лента: `ollama serve && ollama pull bge-m3`, затем `npm run embed:backfill`.
6. (опционально) MCP-сервер:

```bash
cd mcp
npm install && npm run build
# в конфиг ассистента (stdio):
# caseportal-mcp → node <repo>/mcp/dist/index.js
# env: NEXT_PUBLIC_SUPABASE_URL, ключ, MCP_ORG_EMAIL, MCP_ORG_PASSWORD
```

7. (опционально) REST API/webhooks: задайте `SUPABASE_SECRET_KEY` (service role) — создайте ключ через RPC `create_api_key` и вызывайте `/api/v1/...` с заголовком `Authorization: Bearer cp_...`.

## Структура

```
app/
  page.tsx                        витрина: hero + умная лента
  events/[id]                     событие, кейсы, регистрация
  leaderboard                     таблица лидеров (raw / normalized)
  calendar, works, diploma        календарь, галерея работ, дипломы
  login, register                 авторизация (Supabase Auth)
  join/[code], join/org/[token]   приглашения в команду / организацию
  my/                             дашборд организатора
    orgs                          организации (создание, участники, приглашения)
    events/new                    создание события (кейсы, критерии, слепое судейство)
    events/[id]                   статистика, заявки, решения, судьи
    registrations                 мои заявки + загрузка решений
  judge/                          панель судьи (очередь работ)
  judge/review/[id]               оценочный лист
  api/embed                       эмбеддинги (Ollama / OpenAI-совместимый)
  api/v1/                         публичный REST API (events, leaderboard, webhooks)
lib/                              supabase-клиент, auth, api-key auth
mcp/                              MCP-сервер для ИИ-ассистентов
supabase/                         схема и миграции (RLS везде)
docs/API.md                       REST API v1
scripts/backfill-embeddings.mjs   бэкфилл эмбеддингов
```

## Роли и доступ (RLS)

- **Аноним**: читает опубликованные события, кейсы, лидеров.
- **Пользователь**: регистрируется, создаёт свои события, видит свои заявки и решения, загружает решения.
- **Член организации** (owner/admin/manager): управляет событиями организации, заявками, судьями.
- **Судья** (принявший приглашение или автор): видит решения, ставит оценки; при слепом судействе авторство скрыто до публикации итогов.

## Безопасность

- Row Level Security на всех таблицах; сервисная роль используется только сервером для проверки API-ключей.
- API-ключи хранятся как sha256-хэш, отзыв — мгновенный.
- Webhook-подписи: HMAC-SHA256 с секретом на каждую подписку.
